# 元件库存管理

一个管理电子元件库存的命令行工具。所有元件用**标签**描述，支持添加、检索、更改存量。

核心不是增删改查，而是**模糊识别**：电子元件的写法太不统一了，同一个人不同时候会写 `0.1uF` 和 `100nF`，会写 `51R` 和 `51Ω`，会用中文「电容」也可能用代号 `C`。如果匹配只做字符串比较，这个工具就只是个带搜索框的文本文件。所以参数量归一化是整个项目的技术核心。

纯标准库，无第三方依赖，无构建步骤。

---

## 快速开始

```powershell
python inventory.py add C 0805 贴片 100nF 50V --level 3
python inventory.py add R 0603 51Ω 1% --qty 42
python inventory.py add R 0805 51Ω 5% --level 3
python inventory.py add U SOP-8 NE555 --level 0 --note "555 定时器"  # 等同于 --qty 0
python inventory.py --search 51R
```

最后一条会输出：

```
[1]  #2  R  51Ω  1%  0603  存量: 精确 42  ← 51R ≈ 51Ω
[2]  #3  R  51Ω  5%  0805  存量: 多(3)  ← 51R ≈ 51Ω

共 2 条
```

标签是按语义分列显示的，列与列对齐——`R` / `51Ω` / `1%` / `0603` 各占一列。详见「标签的列序与写法」。

行尾的 `←` 后面是**命中原因**——哪个查询词命中了哪个标签。这不是装饰：模糊匹配必须能解释自己，否则一旦出现意外结果，你就再也不敢信它了。

## 命令

### search —— 检索

```
inventory.py search 查询词... [-A|--any] [-n N] [--json]
```

多个查询词之间是 **AND**：元件必须为每个词都提供命中。`-A/--any` 放宽为「任一命中」。

```powershell
python inventory.py --search 51R
python inventory.py --search 电容 100nF      # 同时是电容且有 100nF
python inventory.py --search 51R -n 5        # 最多 5 条
python inventory.py --search 51R --json      # 供脚本消费
python inventory.py --search 电容 电阻 -A     # 任一命中
```

每条结果占一行，行尾的 `←` 是命中原因。有备注的元件，会在自己那一行下面缩进补一行 `备注: ...`；`--json` 结果里也带 `note` 字段。

**`-n N` 只限制显示条数，不改事实。** 匹配到几条就是几条，退出码也不受它影响；真的切掉了，会紧跟一行括号说明告诉你实际匹配了多少条：

```powershell
> python inventory.py --search C -n 1
[1]  #1  C  1uF  16V  MLCC  0805  存量: 多(3)  ← C

共 1 条
（实际匹配 5 条，这里只列前 1 条；用 search ... -n 5 看全部）
```

注意这里有两个数字：`共 1 条` 数的是**列出来的**条数，括号里的 `实际匹配 5 条` 才是**匹配到的**总数。没有截断时括号那行不会出现。

因此 `-n` 必须是正整数。`-n 0` 与负数都以退出码 **2**（用法错误）失败，**不是** 3——退出码 3 始终只表示「库里真的没有」。

不给 `-n` 就全列出来。这一点与交互模式不同：交互模式默认每页 20 条。

`--json` 的形状：

```json
{
  "count": 1,
  "total": 5,
  "query": ["C"],
  "results": [
    {
      "seq": 1,
      "id": "1fc4e867-8824-4f8f-bc53-8ff3cee41ee0",
      "tags": ["C", "1uF", "16V", "MLCC", "0805"],
      "stock": { "mode": "coarse", "level": 3 },
      "note": "",
      "score": 1.0,
      "matches": [{ "token": "C", "score": 1.0, "reason": "C" }]
    }
  ]
}
```

`count` 是 `results` 的条数（**受** `-n` 影响——脚本传了 `-n 5` 就是要 5 条），`total` 是实际匹配到的总数（不受影响）。两者相等就说明没被截断。`score` 与 `matches` 只有 `search` 给，`id` 与 `note` 两个命令都给。

### add —— 添加

```
inventory.py add 标签... [--level 0-4 | --qty N] [--note 文本] [--force]
```

`--level` 是粗略存量，`--qty` 是精确个数，两者互斥。都不给时默认 `0`（无）并给出提示。`--level 0` 与 `--qty 0` 是同一个值——0 不算粗略档，详见「存量」。

```powershell
python inventory.py add C 0805 贴片 100nF 50V --level 3
python inventory.py add R 0603 51Ω 1% --qty 42
python inventory.py add U SOP-8 NE555 --level 2 --note "555 定时器"
```

添加时元件必须凑齐**类型和封装**两类标签（参数可选），缺了会被拦下并告诉你缺什么。其中类型可以自动推断——所以 `add 1uF 16V 0805` 是能用的，它会自己补上 `C`。详见「必需的两类标签」一节。

**与库里已有元件构成包含关系时，命令行报错退出，什么都不写**，确认不是重复录入就补一个 `--force`：

```powershell
> python inventory.py add C 0805 100nF 50V MLCC
错误：新元件 C 100nF 50V MLCC 0805 与库中 1 个元件存在包含关系：
  [1]  #2  C  100nF  50V  MLCC  0805  等价  存量: 多(3)

（未写入。确认不是重复录入的话，加 --force 再执行一次。）
```

同一批电容分两袋放是合法的，所以这不是禁止重复，只是要求你确认一次——交互模式会停下来问，命令行则把判断留给你，用 `--force` 表达。判定规则见「重复录入：包含关系怎么判」。

`--force` 在交互模式下还兼任一个开关：**类型是弱证据推出来的那一问也一起跳过**（见下文的交互模式）。它表达的都是同一件事——「我都看过了，照加」。

### stock —— 更改存量

```
inventory.py stock #编号 [值] [--level 0-4 | --qty N]
```

目标只能是 `#编号`，和 `remove` 一样——改库存得先确认改的是哪一条，模糊定位交给 `search`。值可以直接写在编号后面，不必接选项：

```powershell
python inventory.py stock '#7' plenty     # 极多(4)
python inventory.py stock '#7' 很少        # 极少(1)
python inventory.py stock '#7' level2     # 少(2)
python inventory.py stock '#7' 23         # 精确 23 个
python inventory.py stock '#7' +5         # 在精确存量上加 5
python inventory.py stock '#7' 用掉5       # 减 5
python inventory.py stock '#7' --level 2  # 选项形式照旧
```

`#` 在 Bash 与 PowerShell 里都是注释符，命令行示例一律加引号；交互模式没有 shell，写 `stock #7 plenty` 就行。

新存量会**整个替换**旧的，两种模式不会共存。相对增减是这条规则唯一的例外——它必须在精确存量上用，当前是粗略档会直接报错：

```powershell
> python inventory.py stock '#5' +1
错误：当前存量是「多(3)」，粗略档位没法做相对增减。
先写成精确数（例如 `stock #5 20`）再用 `+N` / `-N`，或者直接用档位词覆盖（例如 `stock #5 少`）。
```

**0 是例外，它可以直接增减。** 粗略档位里只有 1-4 档（极少 / 少 / 多 / 极多）会撞上这条——那几档之间没有公认的「加一」语义。而 0 没有说不清多少的余地，所以精确 0 与「无」是同一个值，新加的元件（默认就是它）可以直接 `stock '#5' +1`。上面那条报错只在当前存量是 1-4 档时出现。

值的全部写法见「存量」一节。

### list —— 列出全部

```
inventory.py list [-n N] [--low] [--json]
```

`--low` 只列出存量偏低的（粗略 0-1，或精确 ≤ 5）。

有备注的元件，会在它那一行下面缩进补一行 `备注: ...`；`--json` 结果里也带 `note` 字段。

`-n` 的规则与 `search` 一致：只切显示、须为正整数、切掉了会说明实际有多少条。给了 `--low` 时那几个字会跟着变，免得读成「库里有这么多条」、或者被引去看全集：

```powershell
> python inventory.py list --low -n 1
#2  C  100nF  50V  MLCC  0805  存量: 极少(1)

共 1 条
（存量偏低的有 2 条，这里只列前 1 条；用 list --low -n 2 看全部）
```

`--json` 的形状与 `search` 相同，只是没有 `query`、`score`、`matches` 三样，`total` 同样是切片前的条数（有 `--low` 时是**过滤后**的条数）。

### remove —— 删除

```
inventory.py remove #编号
```

目标同样是 `#编号`。标签写错了就删掉重录。已删除的序号**不会回收**——删掉 `#5` 之后，新元件拿到的是 `#6`，这样你记下的 `#5` 不会突然指向别的东西。

### 顶层写法

所有命令都支持顶层 flag 形式，与子命令完全等价：

```powershell
python inventory.py --search 51R     # 等价于 inventory.py search 51R
python inventory.py --add C 100nF --level 1
python inventory.py --list
```

## 交互式入口

```powershell
python WarehouseKeeper.py
```

进入一个循环，敲命令、看结果、再敲，不必每条命令重新起一次进程。

交互模式里 `search` 与 `list` 默认每页 20 条（`-n` 可改），切掉了会补一行说明。命令行那边不给 `-n` 就是全列——它还要给管道和 `--json` 用，默认截断会静默改变脚本拿到的东西。

```
元件库存  ·  交互模式
  数据：T:\component-inventory\inventory.json     共 4 条，其中 1 条存量偏低
  输入 help 看命令，quit 退出。

元件库> search 51R
[1]  #2  R  51Ω  1%  0603  存量: 精确 42  ← 51R ≈ 51Ω
[2]  #3  R  51Ω  5%  0805  存量: 多(3)  ← 51R ≈ 51Ω

共 2 条

元件库> stock #2 少
#2  R 51Ω 1% 0603   存量: 精确 42 → 少(2)

元件库> stock #2 42
#2  R 51Ω 1% 0603   存量: 少(2) → 精确 42

元件库> stock #2 -3
#2  R 51Ω 1% 0603   存量: 精确 42 → 精确 39
```

命令名和选项与上面的命令行版本完全一致（`search` / `add` / `stock` / `list` / `remove`），另外多两个：`help` 显示帮助，`selftest` 直接跑一遍内置自检。输入 `help` 看全部说明。

**追问会缩进两格。** 一条命令如果需要你补答（封装、数量、类型确认、包含关系、删除确认），问句和输入点都缩进两格，挂在那条命令下方；追问期间程序自己打印的话（「封装不能为空」这类重问的提示、「看不懂存量写法」那张写法表）同样缩进——**多行的报错整块都缩进**，因为那还是追问的一部分，不是命令的结果。问题一有答案，缩进就结束——「已添加 #3 …」「已取消。」这类结果行回到第一列。

注意其中**数量那一问发生在元件已经入库之后**：元件先写好、拿到编号，才问你要不要补数量。这一问因此没有「取消」——回车、EOF、Ctrl+C 都只是不填，记录留在库里。

于是有一条大致可用的阅读规则：**每条命令输出的第一行一律顶格**（结果、或者错误消息的 `错误：` 那行），下面是缩进的补充说明；而一段开口就在等你输入的缩进块，就是追问。

**`add` 撞上重复时也会问，而且是把相关元件先摊开再问。** 「新元件是已有元件的子集」和「已有元件是新元件的子集」都算，报的是哪一种会写在表格里：

```
元件库> add C 0805 100nF
  新元件 C 100nF MLCC 0805 与库中 1 个元件存在包含关系：
    [1]  #1  C  100nF  50V  MLCC  0805  新元件更宽泛  存量: 多(3)
  仍然添加？(y/N) > y
已添加 #4  C 100nF MLCC 0805
  请输入数量（直接写数字＝精确个数，如 23；或无 / 极少 / 少 / 多 / 极多，英文 none/few/some/many/lots；回车跳过）
  数量 > 20
#4  C 100nF MLCC 0805   存量: 无 → 精确 20
```

回车、EOF、Ctrl+C 都当「否」，和删除确认一样；想在命令里直接跳过这一问，写 `--force`。注意这一问排在封装之后——**要等标签定稿才能比**，自动补上的类型和介质都算数。

答 `n` 时这条命令就到此为止，**不会**先问你一轮数量：数量那一问排在写盘之后，而写盘根本没发生。

**类型的依据是弱证据时，写入前还会先问你一句。** 推断分强弱（详见「必需的两类标签」）：带单位的量（`1uF` → C）和型号表（`1N4148` → D）是硬的，直接补上不回话；惯例、中文描述词、介质这些是**猜**的，猜错了会静默写进盘，所以要先点一次头：

```
元件库> add 2p 2.54
  自动补全类型标签 J，依据：`2p`、`2.54`，按行业惯例
  存成：J 2p 2.54   存量: 无
  按此添加？(y/N) >
已取消。
```

「存成」那行里的存量是**此刻将要写进去的值**。数量那一问在写盘之后，所以这里还没问、显示的是默认的「无」——你答的数量会在随后覆盖它。

那句「依据」和写入之后回显的是**同一句**，写入前看到的与写入后看到的必须逐字一致。确认时还会把定稿后的标签与存量一起摊开——推出来的类型可能正是你不想要的那个（`2p` 在连接器上是脚数，在别处是皮法），而记录一落盘就只能 `remove` 重录。

回车、EOF、Ctrl+C 都当「否」；`--force` 与包含关系共用同一个开关，两问一起跳。这一问排在包含关系之前——先定「这东西是什么」，再比「库里有没有类似的」。**命令行的 `add` 没有这一问**：脚本化录入要的是不被打断，那边靠回显自证。

**`add` 缺封装时会直接问你。** 这是交互模式独有的能力——命令行只能靠封装表识别，认不出就报错；而在这里你会被问一句，**答什么就存什么**，所以表之外的自定义封装名也录得进来：

```
元件库> add 1uF 16V
  请输入封装（如 0805 / SOT-23 / 5x11 / 2.54 / 直插；确实没有就输入 NO PACKAGE）
  封装 > 0805
已添加 #5  C 1uF 16V MLCC 0805
  （自动补全了类型标签 C，依据：`1uF`，单位可以确定）
  （自动补全了介质标签 MLCC，依据：片式尺寸码的电容就是陶瓷的）
  请输入数量（直接写数字＝精确个数，如 23；或无 / 极少 / 少 / 多 / 极多，英文 none/few/some/many/lots；回车跳过）
  数量 > 20
#5  C 1uF 16V MLCC 0805   存量: 无 → 精确 20
```

封装这一问不能空着：直接回车只会重新问一遍（那句长问句只打一次，重问时只重出 `封装 > `）；想取消整次添加按 Ctrl+C。确实没有封装的元件输入 `NO PACKAGE`（存盘统一成 `无封装`）。

**回答会被拆成词。** 你答的是一句话，库里存的是标签，两者不能混为一谈——答 `直插 2.54` 会被拆成两个标签，`2.54` 当封装、`直插` 因为冗余被吸收（和 `add C 直插 5x11 100uF` 一个行为）。换句话说，在 `封装 > ` 处答什么，等价于把那些词追加到刚才那条 `add` 后面。判定顺序是三档：

1. **整句本身就是一个封装名**（`SOT23` / `Case A` / `TO 220` / `NO PACKAGE`）→ 存它的规范写法。带空格的真封装名靠这一档，所以 `Case A` 不会被拆成 `Case` 和 `A` 两条。
2. **拆开以后认得出来**（`直插 2.54` / `0805 100nF`，后面那个例子说明回答里可以顺带带别的标签）→ 按普通标签收下，交给常规的必需标签校验。
3. **怎么都认不出** → 整句当成**一个**封装名存下来。这是录入表外封装的唯一途径，所以不拆散——拆成两条谁也不认，校验会直接报缺封装。

**问完封装还会问一句数量，但这一问发生在写入之后。** 只有在你既没给 `--level`/`--qty`、标签里也没写存量的时候才问。完整顺序是「封装 → 类型确认 → 包含关系确认 → **写盘** → 数量」——也就是说元件先入库、拿到编号，才轮到这一问。

```
元件库> add C 1uF
  请输入封装（如 0805 / SOT-23 / 5x11 / 2.54 / 直插；确实没有就输入 NO PACKAGE）
  封装 > 0603
已添加 #6  C 1uF MLCC 0603
  （自动补全了介质标签 MLCC，依据：片式尺寸码的电容就是陶瓷的）
  请输入数量（直接写数字＝精确个数，如 23；或无 / 极少 / 少 / 多 / 极多，英文 none/few/some/many/lots；回车跳过）
  数量 > 多
#6  C 1uF MLCC 0603   存量: 无 → 多(3)
```

注意「已添加」那行**没有存量**：这一问还没答，最终值由下面那行给出。你答什么，等价于紧接着敲一条 `stock #编号 什么`——同一份实现、同一行回显，所以答案的写法和 `stock` 的值位置完全一样：

- 裸数字 `20` 就是精确 20 个（**标签里不能这么写**，见「存量」一节；值位置只有一个词，没有那个歧义）
- `多` / `极少` / `none` / `level2` / `qty23` 照旧
- `+5` / `用掉2` 也能用——新元件默认是精确 0，而 0 可以直接增减

**答不上来不会丢记录。** 直接回车就跳过，存量留在「无」；**EOF 和 Ctrl+C 同样只是跳过**，元件已经在库里了（这一问没有可取消的东西）。输入看不懂的内容会缩进报错并重新问——整块报错都缩进，因为那还是追问的一部分。真要取消整次添加，得在封装那一问按 Ctrl+C，那时元件还没落盘。

`remove` 和 `stock` 只认 `#编号`。改库存、删元件都是写操作，要定位到确定的一条，所以宁可要求你先把编号查准——编号是永久的，`search` 与 `list` 的输出里每条都带着它。写检索词会被告知这一点：

```
元件库> remove 51R
错误：目标只能写成 #编号（如 #7），实际是 '51R'。
编号是永久的：先用 `search 关键词` 或 `list` 查到它。
```

`remove` 拿到编号之后还会再确认一次，并把完整信息摊开：

```
元件库> remove #2
  即将删除：
    #2  R 51Ω 1% 0603   存量: 精确 42
  （上一版数据在 inventory.json.bak，可以从那里恢复这次删除）
  确认删除？(y/N) > y
已删除 #2  R 51Ω 1% 0603
```

「即将删除」那几行缩进得比输入点更深，是因为它们本身就是那个问题的上下文——你在按 `y` 之前看到的，和将要被删掉的是同一个东西。

### 退出

`quit`（或 `q`、`exit`）是唯一在所有环境下都成立的退出方式，推荐用它。Windows 控制台的 EOF 是 **Ctrl+Z 再回车**；Git Bash 是 Ctrl+D。**Ctrl+C 不会退出**，它只取消当前输入或当前操作——这是 Python 自身的 REPL、bash、psql 的共同行为，免得一次误按丢掉整个会话。

### 平台差异

在 PowerShell、Windows Terminal 这类真正的 Windows 控制台下，**行编辑和上下箭头历史由控制台本身提供**，可以正常翻回上一条命令。但如果 stdin 不是控制台（比如在 Git Bash 里跑，或者用 `< cmds.txt` 重定向），Python 会退化成普通文本读取，**没有任何行编辑**——按上箭头会往行里插入 `^[[A`。这不是这个程序的缺陷，是 Windows 上 `input()` 的能力边界，而 Python 在 Windows 上不内置 `readline`，补上它需要引入第三方包。

### 非交互执行

```powershell
python WarehouseKeeper.py -c "search 0.1uF"
python WarehouseKeeper.py -c "add C 0603 1uF --level 2"
```

不进入循环，执行一条命令后退出，退出码就是那条命令的结果。调试和自动化都能用。

注意 `-c` 走的是**交互语义**：`-c "add …"` 缺封装、缺数量、类型是弱证据推出来的、或者撞上包含关系时照样会追问。

**缺数量不再丢记录。** 无人值守跑 `-c "add …"` 时 stdin 是关着的，数量那一问拿到 EOF 就直接跳过——元件已经写进库了，存量为「无」。也就是说这一条不再需要靠 `--level` / `--qty` 来避免数据丢失。（数量那一问的提示会照常打在输出里，只是没人答而已。）

仍然会取消的是另外三种，它们都排在写盘之前：**缺封装**、**弱证据类型确认**、**包含关系确认**。这三种在 stdin 拿不到答案时走「已取消。」这条路——**而退出码仍然是 0**，看起来像成功。无人值守要写 `--force`（跳过类型确认与包含关系）并保证封装能从标签里查出来。真要在脚本里录元件就用 `inventory.py add`，它撞上包含关系会以退出码 2 报错，绝不静默。

## 存量

两种模式，**互斥**，设置新的会顶掉旧的。

| 模式 | 表示 | 含义 |
|---|---|---|
| 粗略 | `--level 1` | 极少 |
| 粗略 | `--level 2` | 少 |
| 粗略 | `--level 3` | 多 |
| 粗略 | `--level 4` | 极多 |
| 精确 | `--qty 42` | 精确 42 个 |
| 精确 | `--qty 0` | 无 |

**零只有一个形状。** 粗略档位是给「说不清具体多少个」用的，而 0 没有说不清的余地——「大致上没有」和「精确地没有」是同一件事。所以 `--level 0` 存进去的是精确 0，`无` / `level0` / `none` / `empty` / `zero` 这些写法全都产出同一个值，显示统一是 `无`。

这条不是洁癖，它解决一个实际问题：**相对增减只在精确存量上有效**（粗略档之间没有公认的「加一」语义，「多」的下一格是「极多」，「极少」的下一格却是「少」）。新加的元件默认就是 0，如果 0 是粗略档，那 `add` 完想 `stock '#5' +1` 就必然撞报错——最常见的那条路径被挡住，只为了维持一个没有含义的区别。

存量也可以**直接写在标签里**，不必接选项：

```powershell
python inventory.py add C 0805 100nF qty23     # 精确 23 个
python inventory.py add C 0805 100nF level2    # 少(2)
python inventory.py add C 0805 100nF 多         # 多(3)
python inventory.py add C 0805 100nF 很多       # 极多(4)
python inventory.py add C 0805 100nF lots       # 极多(4)，英文
```

中文那五个词就是粗略存量五档的正式名字，另外认几个口语同义词；英文同样五档各占一个词：

| 档位 | 正式名 | 中文也认 | 英文 | 或写 |
|---|---|---|---|---|
| 0 无 * | `无` | `没有` | `none`、`empty`、`zero` | `level0` |
| 1 极少 | `极少` | `很少`、`一点点` | `few`、`scarce` | `level1` |
| 2 少 | `少` | — | `some`、`little`、`low` | `level2` |
| 3 多 | `多` | `不少` | `many`、`several` | `level3` |
| 4 极多 | `极多` | `很多`、`大量` | `lots`、`plenty`、`tons` | `level4` |

\* 0 档那一行的词全认，但它们产出的是**精确 0** 而不是粗略档（见上面「零只有一个形状」）。写法照旧、显示照旧是 `无`，只有存进 JSON 的形状不同。1-4 档是真粗略档，不受影响。

`很少` 归到极少、`很多` 归到极多，是**按语义强度**归位的结果，不是把它们当成「少」和「多」的口语说法——所以五档各有各的口语对应，将来真想区分「多」和「很多」也还有余地。

英文那边是一架**单调阶梯**：`none` < `few` < `some` < `many` < `lots` 恰好五个词，一格一个。它不是逐词翻译（`few` 严格说更贴「很少」），而是让英文自己构成一条刻度——你不必记住哪档对应哪个词，只要知道**词越大库存越多**。顺带补上了「少」这一档，中文这边的 2 档一直空着没有口语同义词。

大小写随意（`NONE` / `None` / `none` 都认），和 `QTY23` / `Level2` 一致。

`no` 刻意**不认**：它是封装哨兵 `NO PACKAGE` 的第一个词，而命令行标签是空格分词的，照文档敲 `add C 0805 100nF NO PACKAGE`（不加引号）时裸 `NO` 会被静默当成存量「无」。`none` 已经覆盖了这个意思，不值得冒这个险。（加了引号的 `"NO PACKAGE"` 是一个完整标签，照常识别成封装。）

英文**只是录入写法**，显示一律是中文（`无` / `极少(1)`）——和项目其余部分一致。`--level` 也只认数字，`--level none` 会报错：它是个显式的数值刻度，`--level none` 比 `--level 0` 还长。

### stock 的值怎么写

`stock` 的值可以直接写在编号后面，也可以走 `--level` / `--qty`。两条路各管一件事：选项是显式的数值刻度，位置值是给人手打的。

| 写法 | 结果 |
|---|---|
| `极少` `少` `多` `极多`，以及上面那整套中英同义词 | 粗略档位 |
| `无`，以及 `没有` / `none` / `empty` / `zero` | 精确 0 个（显示成「无」） |
| `level2` | 粗略 少(2) |
| `23` | 精确 23 个 |
| `qty23` | 精确 23 个 |
| `+5` `-3`，或裸 `+` `-` | 相对增减，裸符号就是加一减一 |
| `加5` `增5` `添5` `补5` `进5` `入5` | 相对增减 +5 |
| `减5` `用5` `耗5` `去5` `出5` `丢5` `损5` `坏5` | 相对增减 −5 |
| `add5` `plus5` `inc5` `gain5` | 相对增减 +5 |
| `sub5` `minus5` `dec5` `use5` `take5` `lost5` | 相对增减 −5 |

中文动词后面可以多一个「掉」，`用掉5` 与 `用5` 等价；英文动词不分大小写。数字省略就是 1——`加` 等于 `+1`，`用掉` 等于 `-1`。

**裸数字是精确个数，不是档位。** `stock #7 3` 设的是「精确 3 个」，要档位 3（多）得写 `多` 或 `level3`。同一个裸数字在 `add` 的标签里却是个普通标签，两边刻意不同：标签是按空格分词的，`0805` 这类封装码一旦被认成个数就成了 805 个。代价是 `stock #7 0805` 真的会设成 805 个——值位置只有一个词，语义明确，不拦。

**`+5` 是「再加 5」，不是「设为 5」。** 要设成 5 直接写 `5`。符号与数字必须连着写，`+ 5` 不认。

**相对增减只对精确存量生效**，而这条实际上是针对 **1-4 档**说的。粗略档位之间没有公认的「加一」语义——「多」的下一格是「极多」，「极少」的下一格却是「少」，中间差着的量只能靠猜。所以当前存量是那四档之一就报错，让你先写成精确数。

**0 不在其列**，因为它干脆不是粗略档（见「零只有一个形状」）。`无` / `--qty 0` / `--level 0` 都是精确 0，可以直接 `stock '#7' +5`——新加的元件正是这个状态，所以 `add` 完紧接着来一条 `stock '#7' +1` 是能用的。减到负数同样报错，要清零写 `stock #7 0`。

**`多` / `少` / `low` 是档位词，不是增减词。** 它们已经占着「粗略 3」「粗略 2」的位置，同一个词在同一个位置有两种解释是最坏的一种歧义，所以 `多5` 一律报「看不懂」。同理没收的还有 `到` / `满` / `空`（「到5」既可能是「到货 5 个」也可能是「达到 5」）和 `up` / `down` / `in` / `out`（太短，方向靠猜）。

**标签和选项只能给一个**，同时写会被拦下（`add C 0805 100nF qty23 --qty 5` 报错）。存量标签在存盘时会被摘掉——存量是独立字段，从来就不在标签里。

互斥不是靠约定，是靠数据结构保证的：JSON 里存成 `{"mode": "coarse", "level": 3}` 或 `{"mode": "accurate", "count": 42}`，两种模式各是一个不同的对象形状，结构上就不可能同时存在。

「无」存的是 `{"mode": "accurate", "count": 0}`——它和 `--qty 0` 是同一个值，只是显示成 `无`。旧文件里如果还有 `{"mode": "coarse", "level": 0}`（手工写的，或者零统一之前留下的），程序照样读得懂，并且会在下一次写盘时折成精确 0，不需要任何迁移步骤。

## 必需的两类标签

每个元件必须凑齐**类型和封装**，缺了会被拦下。这两类的判定方式完全不同，值得分清楚——**只有类型有推断引擎**，封装只能查表。此外还有第三类**参数**：它不必需，但会被识别，并决定显示列序与检索权重（见「参数：可选的第三类」）。

### 类型：可以推断

用类型码（`C` / `R` / `L` / `D` / `Q` / `U` / `J` / `SW` / `XTAL` / `LED` / `OPTO` / `FUSE` / `POT` / `RELAY` / `BZ` / `ANT` / `BAT` / `TP` / `X`）或者它的中文别名（`电容` / `电阻` / …）写出来就行。没写的话，按下面的顺序推断，推出来的会**自动补进标签并存盘**，同时告诉你依据：

```powershell
> python inventory.py add 1uF 16V 0805
已添加 #5  C 1uF 16V MLCC 0805   存量: 无
  （自动补全了类型标签 C，依据：`1uF`，单位可以确定）
  （自动补全了介质标签 MLCC，依据：片式尺寸码的电容就是陶瓷的）
```

推断的来源有强有弱，取最强的一条；**同强度内出现两个不同的码就报错**，绝不按标签顺序任选。

**强档（强度 2）——带明确单位的量，和常见型号。**

- **单位指明维度**：`1uF` / `100nF` / `22pF` → 电容，`51Ω` / `51R` / `0R` → 电阻，`4u7H` / `10uH` → 电感。
- **型号表**：`1N4148` → 二极管、`2N2222` → 三极管、`PC817` → 光耦、`NE555` / `STM32F103` → 芯片。这一档必须排在惯例之前：`parse_quantity("1N4148")` 会把 `N` 当成纳、返回 `1.4148e-9`，不拦住的话一个二极管就会被推断成**电容**。
- **连接器系列**：`XH` / `VH` / `PH` / `ZH` / `GH` / `EH` / `MX` / `JST`，三种写法都认——裸的（`XH` / `jst`）、带脚距连写的（`XH2.54` / `ph2.0`）、带连接符的（`JST-XH` / `XH-2.54`）→ 连接器。大小写不分，因为系列名不携带大小写语义（型号才有：`ss14` 不是 `SS14`）。裸系列名只有两个字母，本来是会被「少于三个字符不看」那道闸挡下的——那道闸防的是 `M7` / `K2` 这类丝印与 EIA 容差码碰撞，而这里是一张封闭白名单，撞车面不同，所以它是那道闸唯一的例外。

**弱档（强度 1）——惯例、介质、中文描述词、频率。** 它们彼此**平级**，所以互相矛盾时会如实报出来而不是静默选一个：

- **惯例裸前缀**：`k` → 电阻、`p` → 电容、大写 `M` → 电阻。`10k` 是 10kΩ，`1M` 是 1MΩ，`22p` 是 22pF。
- **引脚数 `Np` / `NP`——只在连接器语境下**：`2p 2.54` / `排母 3p 2.54` / `XH 4p` 里的 `2p` / `3p` / `4p` 都是「N 脚」，指向连接器，**不是皮法**。判据是整批标签里有没有连接器证据：指向 J 的类型词与别名（`排母` / `排针` / `连接器` / `端子` / `header`）、指向 J 的中文描述词（`杜邦` / `牛角`）、连接器系列名（`XH` / `jst`…），以及**脚距封装**（`1.27` / `2.54` / `3.81` / `5.08` / `7.62`）。没有这些证据时一切照旧：`22p` 仍是 22pF，`add 2.54` 仍报缺类型，`40P` 单独出现什么都不是。
  它是**改判**而不是新增证据——`Np` 本来会推出一条错的 C 候选（皮法），有连接器语境时换成 J。所以它压不过任何别的证据（`22pF 2.54` 有单位，仍是电容），只在自己是唯一候选时才说话。判据看的是整批标签而不是这一条自己：`add 2p 2.54 jst XH` 里的证据全排在 `2p` 后面。
  脚距那一档有假阳性面：直插瓷片、薄膜电容也用 `2.54` / `5.08` 脚距（库里 `C 100nF 50V 瓷片 2.54` 就是）。所以**想录 2.54 脚距的 22pF 瓷片就写 `22pF`，或显式写 `C`**；写成 `22p 2.54 瓷片` 会因为脚距指向 J、介质指向 C 而报同强度冲突——这是设计如此，宁可报错也不替你选。
- **介质词**：`MLCC` / `电解` / `钽` / `薄膜` / `云母` 指向电容。所以 `薄膜 104 100V` 推得出类型，尽管 `104` 和 `100V` 单独都推不出来。
- **中文描述性词**：`色环` / `金属膜` / `碳膜` / `水泥` → 电阻，`工字` / `磁环` / `磁珠` → 电感，`轻触` / `拨动` / `船型` / `微动` → 开关，`牛角` / `杜邦` → 连接器，`微调` → 电位器，`纽扣` / `锂电` → 电池，颜色词（`红` `绿` `蓝` `黄` `白` `橙` `紫` `暖白` `冷白` `rgb` `三色` `七彩`）→ LED。于是 `直插 5mm 红` 是 LED、`轻触 6x6x5` 是开关。
  有歧义的属性词刻意不收：`功率`（功率电阻 / 功率电感）、`绕线`（绕线电阻 / 绕线电感）、`薄膜`（薄膜电容 / 薄膜电阻）。
- **频率兜底**：频率单独出现时推成晶振，`3225 16MHz` → `XTAL`。它压不过型号表和显式类型——`STM32F103C8T6 16MHz` 仍然是芯片，因为那里的 16MHz 说的是主频。

弱档平级有个直接好处：`薄膜 100k` 会报「介质指向 C、惯例指向 R」的冲突。`薄膜` 既能指薄膜电容也能指薄膜电阻，本来就只配当弱证据。

**刻意不猜的几种**，会直接报错让你写明：

- **`u` 前缀**——`4u7` 既可能是 4.7µF 电容也可能是 4.7µH 电感，两者都常见，靠数值大小区分会在最常用的 1µ~100µ 区间失效。写 `C 4u7` 或 `L 4u7`。
- **`n` 前缀**——同样的两可，只是没 `u` 那么显眼：`100nH` 在 0805 电感里是常规值，和 `100nF` 一样常见。写 `100nF` / `100nH`，或者 `C 100n` / `L 100n`。
  它只在**没有别的类型证据**时才拦：`100nF`（有单位）、`L 100n`（有类型）、`MLCC 100n`（有介质）都不受影响。
  顺带一提 `p` 不在此列——`pH` 几乎不存在，`22p` 猜电容是安全的。`p` 与 `n` 写法对称而命运不同，这是照现实中哪个更常见定的，不是照对称性定的。但要留意它在**连接器语境下会整个让位**给「N 脚」（见上面弱档那条）：`2p 2.54` 是 2 脚连接器，不是 2pF。
- **大写 `K`**——`104K` 是 EIA 容差码（100nF±10%），`470K` 是 470kΩ，两者结构上完全同形、无法区分。写小写 `k` 或者显式给类型。
- **`m` 前缀**——mΩ / mH / mF 三可。
- **电压、电流、功率**——`16V` 的可能是电容、电阻、二极管、MOS，指向不了唯一类型。
- **整数部分为空的短形态**——`M7` 是常见的二极管丝印，但 `M` 会被当成兆（`parse_quantity("M7")` 给出 700000）。

### 封装：查表识别

封装靠名单识别，一共三类。

**半导体与片式元件的封装**——片式尺寸码（`0402` `0603` `0805` `1206` `2512` …）与 IC、分立器件封装（`SOT-23` `SOD-123` `DIP-8` `SOIC-14` `SOP-8` `ESOP-8` `QFN-32` `TO-220` `DO-41` …）。分隔符和大小写不敏感，`SOT-23` / `SOT23` / `sot 23` 是同一个东西，搜 `SOT23` 也能找到写成 `SOT-23` 的元件。

**带散热焊盘的 SOP 系自成一族，不和 `SOP` 混同。** `ESOP-8`（E 是 exposed pad）底下多一块散热焊盘，立创 EDA 里是独立封装，照着 `SOP-8` 下单会买错，所以两者**不合并**。同一块焊盘在不同厂牌下还有别的名字：`HSOP-8`（H 是 heat sink）归到 `ESOP-8`，`HTSSOP-16` 归到 `ETSSOP-16`——一个形状只留一个规范名。后缀写法 `SOP-8_EP` / `SOP8-EP` 与 E 前缀说的是同一件事，也归到 `ESOP-8`。`SO-8` 则是 `SOIC-8` 的另一种叫法。这些归一只发生在**判决与查询期**，存盘保留你写的字（见「标签的列序与写法」）。

**安装方式词**——`贴片` / `直插` / `SMD` / `THT`。严格说这不是封装而是安装方式，但 `C 贴片 100nF` 这种写法太常见，所以也收进来。

**机械尺寸**——有一大类元件根本没有半导体封装，它们用尺寸、脚距、Case 码来描述，这些和 `SOIC` / `0805` 一样，回答的都是「这个元件长成什么形状」：

| 写法 | 用于 |
|---|---|
| `A` `B` `E`、`Case C`、`C型`、`D-Case` | 钽电容的 Case 码 |
| `5x11` `6.3x11` `8x12`（也可写 `5x11mm`） | 圆柱铝电解的「直径 x 高」 |
| `2.54` `5.08` `1.27` `3.81` `7.62` | 脚距 |
| `5mm` `3mm` `8mm` `10mm` | 直插 LED 的直径 |
| `18650` `21700` `14500` `16340` | 电池型号 |
| `1x40` `6x6` `6x6x5` `5x20` | 其它尺寸码 |

脚距只收英寸换算值，不用通用的「小数点数字」正则——因为 `0.5` / `1.5` / `2.0` 都是**合法的电阻值**，吞掉它们等于把参数当成了封装。

尺寸码结尾的 `mm` 可有可无，`5x11mm` 和 `5x11` 归一成同一个封装，搜哪个都能找到对方——规格书上印的就是带单位的那种写法。单位**只在这一个分支里剥**：`5mm` 是直插 LED 的直径，走上面那张白名单，全局剥 `mm` 会把它变成裸 `5`，那张白名单就永远命不中了。

钽电容的裸单字母只认 `A` / `B` / `E`。`C` 和 `D` 是类型码，写 `C 10uF` 时那个 `C` 会被当成电容类型，永远走不到封装这一层；要表达 Case C 得写 `Case C` 或 `C型`。

**封装只存一个，安装方式靠派生。** `C 直插 5x11 100uF` 里 `直插` 和 `5x11` 都命中封装，而封装是单值字段——取的是**更具体的那个**（`5x11`），安装方式太泛，一旦有真正的封装就让位。被让位的 `直插` 不留在标签里，它本来就是 `5x11` 的派生结果，留着只是重复：

```powershell
> python inventory.py add C 直插 5x11 100uF 25V
已添加 #1  C 100uF 25V 5x11   存量: 无
  （`直插` 已并入封装 5x11：这个封装本身就说明了安装方式）
```

但 `直插 0805` 这种自相矛盾的组合**不会**吸收（保留下来让你看见），`直插 18650` 也不吸收（`18650` 派生不出安装方式，那个标签还有信息量）。

**搜「直插」靠派生，不靠标签。** 即使标签里根本没有「直插」两个字、只写了 `5x11`，`search 直插` 照样找得到——圆柱铝电解的尺寸本身就说明了它是直插：

```powershell
> python inventory.py --search 直插
[1]  #1  C  100uF  25V  5x11  存量: 无  ← 5x11（直插）
```

判定表覆盖：片式尺寸码与除 DIP 外的半导体封装（含 `ESOP-8` / `HTSSOP-16` 这些散热焊盘封装）→ 贴片；`DIP` / `PDIP` / `TO-92` / `TO-220` / `DO-35` / `DO-41` / 脚距 / LED 直径 / 圆柱铝电解尺寸 → 直插；`TO-252` / `TO-263` → 贴片（它们就是 DPAK / D2PAK）。

判不出来的一律不猜：`6x6x5` 的轻触开关直插贴片都有，`18650` 电池两种都有，`无封装` 更无从谈起。这只是意味着搜「直插」时不会命中它们，不会产生错误结果。

`6.3x5.4` 是个有意思的反例：贴片铝电解的标法也是「直径 x 高」，但高小于直径，正好被「第二个数更大」这条判据排除在外——不用另建一张例外名单。

**表认不出来的会被拦下**，提示你补一个：

```
错误：没有找到封装标签。
  标签：C 1uF 16V
  补法：加上封装，例如  C 0805 100nF 50V
  常见封装：0402 0603 0805 1206 / SOT-23 SOD-123 / DIP-8 SOIC-14 / 直插 贴片
  若这个元件确实没有封装（散装、模块、自制件、电池座等），写  无封装
```

散装件、拆机件、自制模块、电池座、测试点这些**本来就没有封装**，写 `无封装` 即可（也接受 `NO PACKAGE`，存盘统一成 `无封装`，所以 `search 无封装` 能一次列全）。

在交互模式下，缺封装时会直接问你（见「交互式入口」）。回答先按整句查表，认得出就用规范写法；认不出就拆成词和已有标签拼回去用同一套 `classify_tags` 重判，判得出就按普通标签收下；还是认不出才整句当成一个封装名存下来——这是录入表外封装的唯一途径，也是 `NO PACKAGE` 这类带空格哨兵仍然有效的原因。

### 参数：可选的第三类

**参数不是必需项**——类型和封装齐了就能录入，一个参数也没有也照收。早先的版本要求「除了类型和封装，至少还要有一个参数标签」，但它误伤了「封装本身就是全部规格」的元件：`add 排针 2.54 极多` 会被拦下，而 2.54 的排针确实没有别的可写。`C 0805`、`R 0603` 这类漏写数值的写法现在也不再被拦——这是**有意的宽松**，因为那条规则本来就只管有没有、不管对不对（把 `100nF` 拼成 `100nnF` 照样通过），拦不住拼写错误，却会挡住合法录入。

参数仍然会被识别，也仍然有用：它决定每个标签落在哪一列（主值 / 电气参数 / 其它），进而影响 `canonical_tags` 的列序、检索权重与包含判定。所以能写就写：

```powershell
> python inventory.py add C 0805 100nF 50V
```

注意 `1x40` / `2.54` / `6x6` / `5x20` 都算**封装**（见上一节），写了它们并不等于写了参数——只是这不再构成拦阻。

排针 `J 2.54 1x40 40P` 里的 `40P`、测试点的 `1.0`、模块的型号，都不是可解析的物理量，照旧原样收下。`40P` 是引脚数的大写写法——连接器语境下它与小写 `2p` 同等对待（`add 2P 2.54` 就是 2 脚连接器），但**单独出现时什么都不是**：只写 `40P` 会被照常拦下报「无法确定元件类型」。

### 介质：电容的构造

电容还有一个「构造」维度——**MLCC**（陶瓷）、**电解**、**钽**、**薄膜**、**云母**。它是参数的一种，不是第四类标签。

这五个词还能**推出类型**：它们指的都是电容的构造方式，出现即指向 `C`。所以 `薄膜 104 100V` 能过校验，尽管 `104` 和 `100V` 单独都推不出类型。强度压在弱档（见「类型：可以推断」），所以 `薄膜 100k` 会如实报出「介质指向 C、惯例指向 R」的冲突，而不是替你选一个。

这几种写法**互相检索得到**，所以你不必记住自己是按哪种写的：

```
MLCC  ← MLCC / mlcc / 陶瓷 / 瓷片 / 陶瓷电容 / 瓷片电容 / 独石
电解  ← 电解 / 铝电解 / 电解电容 / 铝电解电容
钽    ← 钽 / 钽电容
薄膜  ← 薄膜 / 薄膜电容 / 涤纶 / 聚酯
云母  ← 云母 / 云母电容
```

**片式封装的电容会自动补上 `MLCC`**——钽电容用 A/B/C/D/E case 码而不是 0805，铝电解根本用不了这个尺寸，所以「片式尺寸码 + 电容」在实践中基本等同陶瓷：

```powershell
> python inventory.py add C 0805 100nF 50V
已添加 #1  C 100nF 50V MLCC 0805   存量: 无
  （自动补全了介质标签 MLCC，依据：片式尺寸码的电容就是陶瓷的）
```

之后 `search MLCC`、`search 陶瓷电容`、`search 瓷片` 都能搜到它。

**直插的陶瓷电容不会被自动补**，因为同一个「直插」下可能是陶瓷圆片、电解圆柱、薄膜方块，推不出来。这类元件要你自己写，写在标签里就行：

```powershell
python inventory.py add C 直插 5.08mm 100nF MLCC --level 3
```

电解和钽从来都靠显式标注，系统不猜。你写 `电解电容` 或 `电解` 都行，`search 电解电容` 只出电解的，不会带上 MLCC。

有个例外要留意：如果你写的是片式**薄膜**电容（`C 0805 100nF 薄膜`），系统看到你已经标了介质，就不会再补 `MLCC`。

## 模糊识别的规则

### 参数量等价

同一物理量的不同写法会被归一化到同一个值再比较。

**单位换算与 SI 前缀**（`p` 皮、`n` 纳、`u` 微、`m` 毫、`k` 千、`M` 兆、`G` 吉）：

```
0.1uF  ≡  100nF  ≡  1e-7F  ≡  100NF  ≡  1e-7     （在电容元件上）
51R    ≡  51Ω    ≡  51ohm ≡  51欧    ≡  51       （在电阻元件上）
```

`µ`（U+00B5）、`μ`（U+03BC）、`u` 三种写法等价；`Ω`（U+2126）和 `Ω`（U+03A9）也等价。全角数字会自动转半角。

**中缀记号**——字母夹在数字中间当小数点用：

```
4R7   = 4.7Ω        1k2  = 1200        4u7  = 4.7µ
R47   = 0.47Ω       2M2  = 2.2M        4n7  = 4.7n
0R05  = 0.05Ω
```

**大小写敏感**：`m` 是毫，`M` 是兆，`1M` 和 `1m` 相差九个数量级，绝不混淆。这是本工具最危险的一个坑，所以哪怕用户写错大小写（`100NF`）会兜底纠正，`m`/`M` 也永远不兜底。

**裸数字靠元件上下文推断**：搜 `51` 时，如果元件是电阻，就按 51Ω 解释；如果元件是二极管（耐压维度），就按 51V 解释。所以 `--search 51` 会命中 51Ω 电阻但**不会**命中 51V 稳压管。维度歧义推迟到有上下文时才消解，因为脱离上下文猜维度一定会猜错。

**封装代码不会被当成物理量**：`0805`、`0603`、`1206` 这些永远不会被解释成 805Ω、603Ω。前导零是封装的特征。

### 类型别名

中文、英文、缩写都能互相匹配，双向都成立：

```
电容 / 电容器 / cap / capacitor  ⟷  C
电阻 / 电阻器 / res / resistor  ⟷  R
电感 / 电感器 / ind / inductor  ⟷  L
二极管 / diode / 肖特基 / 稳压管 / 齐纳  ⟷  D
三极管 / 晶体管 / bjt / mos / 场效应管  ⟷  Q
芯片 / ic / 集成电路 / 运放 / mcu / 单片机  ⟷  U
开关 / S / switch / 按键 / 按钮  ⟷  SW
晶振 / 晶体 / crystal  ⟷  XTAL
保险丝 / 熔断器 / fuse  ⟷  FUSE
电位器 / 可调电阻 / trimpot  ⟷  POT
```

完整清单见 `inventory.py` 里的 `TYPE_ALIASES`。还包括 `J` 连接器、`LED` 发光二极管、`OPTO` 光耦、`RELAY` 继电器、`BZ` 蜂鸣器、`ANT` 天线、`BAT` 电池、`TP` 测试点、`X` 跳线。

单字母代号可以直接搜：`R` / `C` / `L` / `D` / `Q` / `U` / `J` / `X` 的规范码本身就是单字母，开关的规范码是 `SW`，同时也收 IEC / GB 的 `S`——所以 `search S` 和 `search SW`、`search 开关` 结果一致。

除了学名和缩写，还有一批**描述性词**能推出类型，但它们不算「类型别名」——`色环` / `金属膜` / `碳膜` / `水泥` 指向 `R`，`工字` / `磁环` / `磁珠` 指向 `L`，`轻触` / `拨动` / `船型` / `微动` 指向 `SW`，`牛角` / `杜邦` 指向 `J`，`微调` 指向 `POT`，`纽扣` / `锂电` 指向 `BAT`，颜色词指向 `LED`。

区别在**强度**，而且这个区别是必要的：类型别名是显式的（强度 3），描述性词是弱证据（强度 1），和介质、惯例同级。所以你写 `红 100nF` 时它判成**电容**而不是 LED——单位证据压过了颜色。但 `红` 单独出现时，它会补全成 `LED` 并存进标签，因为「红」是描述颜色、不是声明类型。

有歧义的属性词不收：`功率`（功率电阻 / 功率电感）、`绕线`（绕线电阻 / 绕线电感）、`薄膜`（已在介质表里）。

**复合词**会拆成「修饰语 + 主词」，**两者都要满足**才算命中：

```powershell
python inventory.py --search 贴片电容    # 会命中「贴片」+「C」，不会命中只有「贴片」的电阻
python inventory.py --search 金属膜电阻  # 归约到 R
```

### 匹配的层次

对每个查询词，按优先级依次尝试，**首个成功即返回**：

1. **句柄** —— `#7` 匹配序号；`9f1c4e2a` 匹配 id 前缀。这一层服务于**检索**：`search #7` 和 `search 9f1c4e2a` 都成立。写操作不走这一层——`remove` / `stock` 只认 `#编号`，id 前缀只在检索里管用。
2. **物理量等价** —— 用元件自身的类型推出维度，再比较数值。
3. **类型归约** —— 归约到规范码后比较（`电容器` 与 `C` 都归约成 `C`）。
4. **介质归约** —— 让 `陶瓷` / `瓷片` / `MLCC` 互相检索得到。
5. **封装归约** —— 让 `A` 与 `Case A`、`SOT23` 与 `SOT-23` 互相检索得到。
6. **字符串全等**。
7. **安装方式归约** —— 搜 `直插` 能命中只写了 `5x11` 的元件。
8. **子串**。

中间那几层**归约**是这套工具的核心：把查询词和标签都归到同一个规范域再比，于是「按哪种写法录的」不影响「按哪种写法搜」。它们排在字符串层之前或之后是有讲究的——类型、介质、封装归约排在全等之前，是为了让别名也能拿满分；安装方式归约排在之后，是因为标签里真写了「直插」的元件理应比靠封装推出来的拿更高分。

子串匹配带**边界检查**：`100nF` 不会命中 `1100nF`，因为匹配位置的前一个字符是数字、不构成词边界。

单字符的**子串**匹配被刻意禁用——放开的话，搜 `C` 会命中所有含 c 的标签。所以单字符查询一律走类型归约层：别名表里收了的 `S`、`C` 能精确命中对应类型，而表外的单字母不会四处误匹配。代价是纯字母的两字标签（`SR`、`LS` 这类）会被当成两个单字母代号切段，从而被判成类型——这是单字母代号换来的模糊识别能力，不必为它绕路。

### 重复录入：包含关系怎么判

录入时只问一件事：**新元件的标签集合和某条已有元件，在「同一条信息的另一种写法」这个意义下，是不是一个包含另一个。** 三个说法，主语一律是**新元件**：

| 关系 | 含义 | 表格里写 |
|---|---|---|
| 等价 | 互相包含 | 等价 |
| 子集 | 新元件更宽泛（信息更少） | 新元件更宽泛 |
| 超集 | 新元件更具体（信息更多） | 新元件更具体 |

判据是「**字面相同** 或 **分层匹配得分 ≥ 0.9**」。0.9 这一档正好把「同一条信息的另一种写法」全包了进来：字符串全等（1.0）、双方维度都明确的物理量等价（1.0），以及类型 / 介质 / 封装 / 安装方式四种归约（0.9）。于是下面这些在判定里都是同一条：

```
10k ≡ 10kΩ     0.1uF ≡ 100nF     51R ≡ 51Ω
瓷片 ≡ MLCC     电解 ≡ 铝电解     直插 ≡ 2.54（安装方式由封装派生）
```

**子串层被排除在外。** 它双向对称，拿来做包含判定会把「更宽泛」判成「等价」，方向还会翻——`共阴` 子串命中 `共阴绿红`，反过来 `共阴绿红` 也子串命中 `共阴`，两边都成立，于是 `led 2.54 共阴` 会被说成和 `led 2.54 共阴绿红` 等价。检索要的是召回，包含要的是精确，两者共用同一套分层，但不能共用门槛。

字面相同的快速通道是为裸前缀留的：`3p` 这种量没有维度（`parse_quantity("3p")` 得到的 `dim` 是 `None`），而元件又没有类型标签给得出 hint 时，两条一模一样的 `3p` 只能拿 0.70，会被 0.9 挡在门外——`排母 3p 2.54` 录重的那一对正是这么漏掉的。

判定用的也是**定稿之后**的标签：自动补上的类型与介质、以及存盘前的规范化都算数，所以 `add 0805 100nF 50V` 补出 `C` 之后照样能和已有电容比出关系来。

## 标签的列序与写法

标签按语义分成六列，列序固定，同一个结果集里列与列对齐：

```
类型 · 主值 · 电气参数 · 介质 · 封装 · 其它
```

```
[1]  #1  C  100nF  50V  MLCC  0805  存量: 多(3)  ← C
[2]  #3  C  100nF  50V  瓷片  2.54  存量: 多(3)  ← C

共 2 条
```

这个顺序是有读法的：`C` 和 `100nF` 是元件的身份，挨在一起；耐压、功率、容差是附在它后面的条件；介质说明它是哪一类构造；封装收口。从左到右读下来就是一句「一个 100nF、耐压 50V 的 0805 陶瓷电容」。型号算主值——对 `D 1N4148 SOD-123` 来说，`1N4148` 就是它的身份，和 `1uF` 之于电容没有区别。

**认不出语义的标签排在最后。** 颜色词（`黄`）、描述词（`共阴绿红`）、介质码（`X7R`）、型号表外的丝印都进「其它」列。它们不影响识别，插在中间只会打断前面几列的节奏。

**同一列里的多个标签保持你写的相对顺序**，合起来占一个单元格（`R 色环` 是一个格子）。

**缺的列留空。** 一行用不到的列就空着，不补占位符——`list` 里那几条电阻，「电气参数」和「介质」两格是空白，但「存量」仍在所有行的同一列上：

```
#1  C  100nF  50V  MLCC  0805   存量: 多(3)
#2  R  51Ω    1%         0603   存量: 精确 42
#4  U  NE555             SOP-8  存量: 无
```

反过来，**整个结果集里没有一行用到的列不会出现**——上面这张表就没有「其它」列。所以搜电阻时不会平白多出「介质」那一段空白。

单行显示的地方（`add` / `stock` / `remove` 的回显）只有顺序，没有对齐——没有并排的行，就没有可对齐的对象。

### 写法在存盘时统一

下面这些是同一个量的不同写法，**存盘时**会归到一个规范形式：

| 改前 | 改后 | 说明 |
|---|---|---|
| `51r` `220R` `150R` | `51Ω` `220Ω` `150Ω` | 电阻符号统一成 `Ω` |
| `10kR` `1MR` | `10k` `1M` | 带非歧义前缀时省掉冗余的 `Ω`，`10k` 已经是本工具认的电阻写法 |
| `1mR` | `1mΩ` | 例外：`m` 是歧义前缀（`1m` 说不清是毫欧还是别的），Ω 得留着 |
| `16v` `0.25w` | `16V` `0.25W` | 单位后缀统一成大写符号 |

**只改写「数字 + ASCII 单位简写」这一种形态，其余一个字符都不碰。**

- 不动的：中缀记号（`4k7` / `1k2` / `0R05`）、裸数字（`0805` / `2.54` / `1000`）、中文单位（`1欧` / `1伏` / `1瓦`）、容差（`1%`）、型号（`1N4148`），以及全部类型词、介质词、描述词、封装名。它们是**你的词汇**，不是拼写错误的来源。
- **不做浮点往返**：`0.1uF` 不会因为「换算成 100nF 更整齐」而变，`1e-7F` 也不会被重排成别的写法。重新格式化数值会连「我当初写的是多少」一起抹掉，而这个库的价值恰恰在于它记的是你写的东西。
- **`M` 与 `m` 永远不互换**（`1M` 是兆，`1m` 是毫，差九个数量级）。

**规范化和迁移是同一件事。** 规范形式由 `canonical_tags()` 产出，而**每次写盘前都会对库里的每条记录跑一遍**——所以你改一条记录，全库的标签会一起收敛到规范写法与列序，不需要单独的迁移命令。它幂等，第二遍不会再变；迁移前的那一版原封不动落在 `.bak` 里。

这是有意的取舍：代价是「改一条会碰全库」这个隐性副作用，换来的是零迁移成本。每条记录的 `updated_at` 不动——规范化改的是标签的写法和顺序，不是元件的内容。

## 数据文件

默认是脚本同目录的 `inventory.json`，可以用 `--file` 或环境变量 `COMPONENT_INVENTORY_FILE` 覆盖。

```json
{
  "schema_version": 1,
  "next_seq": 3,
  "components": [
    {
      "id": "9f1c4e2a-7b3d-4f88-a1c2-0e5d6b7a8c90",
      "seq": 1,
      "tags": ["C", "100nF", "50V", "MLCC", "0805"],
      "stock": { "mode": "coarse", "level": 3 },
      "note": "",
      "created_at": "2026-10-02T22:54:00+08:00",
      "updated_at": "2026-10-02T23:10:00+08:00"
    }
  ]
}
```

几点设计说明：

- 标签以**规范形式**存盘：写法统一过（`51r` → `51Ω`），顺序按语义列排好（见「标签的列序与写法」）。查询期的归一化仍然照做，所以改进归一化规则时不需要数据迁移，重新加载即可；而写法和列序的变更会在下一次写入时自动落到全库。
- 文件是 UTF-8 无 BOM、换行 LF、中文不转义，可以直接手工编辑。
- `id` 是 UUID，永不变更，用于合并两份库存；`seq` 是给人看的短句柄，只增不减。
- 每次写入前会把上一版另存为 `inventory.json.bak`。写入是原子的（同目录临时文件 + `os.replace` 替换），写到一半断电不会留下截断的文件。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 一般错误（IO 等） |
| 2 | 用法错误 / 结果有歧义未消解 |
| 3 | 未找到 |
| 4 | 数据文件缺失或格式非法 |

```powershell
python inventory.py --search 51R
if ($LASTEXITCODE -eq 3) { "库里没有 51Ω 电阻" }
```

**`-n` 不改变任何退出码。** `-n 0` 与负数是退出码 2 的用法错误，`3` 始终只表示「库里真的没有」——上面这段判断因此是可靠的。这正是本轮修掉的那个洞：以前 `search 51R -n 0` 会拿一个空切片冒充「没搜到」，把这段脚本判成假否定。

## 已知限制

- **`电阻电容` 这类把一个类型词并列的写法搜不到东西。** 它会被展开成 `R` + `C`，按「两者都要满足」处理因而永远为空。请用 `-A` 或分开搜。
- **前导零的封装代码不做数值推断，无前导零的会。** `0805` / `0603` 永远不会被解释成 805Ω / 603Ω。而 `1206` 在电阻元件上仍可能被当成 1206Ω——不过它同时也是片式尺寸码，所以绝大多数时候会按封装匹配上。
- **自动补进去的类型标签、被吸收掉的冗余标签，都无法和手写的区分。** 数据里没有记录哪个 `C` 是你写的、哪个是工具补的，也没有记录哪个 `直插` 是被吸收的。所以将来规则改进了，盘里已有的记录不会重新推断一遍类型，只能手工改标签。（标签的**写法与列序**是另一回事——它每次写盘都会自动规范化，见「标签的列序与写法」。）
- **大写 `K`、`u`、`n` 前缀不推断，要多打一个字符。** `470K` 和 EIA 容差码 `104K`（= 100nF）结构上同形；`4u7` 与 `100n` 都是电容电感两可——4.7µH 和 100nH 一样常见。三者都拒绝推断，而且只在**没有别的类型证据**时才拦：`100nF` / `L 100n` / `MLCC 100n` 都不受影响。这是拿一点麻烦换「不把猜错的结果写进盘」。`p` 不在此列，因为 `pH` 几乎不存在。
- **`M7` 这类两字符丝印认不出来。** `M7` 是 SMA 封装的 1N4007，但它和「7MΩ」结构完全同形，规则上区分不了。要显式写 `D SOD-123 M7`。
- **安装方式靠封装派生，封装判不出来时也就派生不出来。** `6x6x5` 的轻触开关、`18650` 电池两种安装方式都有，系统不猜，所以搜「直插」/「贴片」都不会命中它们。派生也依赖判定表的正确性：`TO-252` 这类同族内直插贴片混杂的封装是按编号逐个判的，遇到没收录的编号会返回「不知道」。
- **冗余的安装方式标签会被删掉。** `add C 直插 5x11 100uF` 存盘时 `直插` 会被吸收（有 `5x11` 就足够表达安装方式），并打印一句说明。自相矛盾的组合（`直插 0805`）和派生不出安装方式的组合（`直插 18650`）不会被吸收。能被吸收的只有两种：安装方式词本身，以及同一个封装被写了两遍（`5x11mm 5x11`，两种写法归一后相同）。两个**不同的**封装即使都是贴片（`SOIC-8` 与 `TSSOP-16`）也不算冗余，不会互相吸收——它们是两个形状，替你删掉一条等于静默丢信息。吸收只在 `add` 时发生，盘里已有的记录不会因此被改写。
- **`_EP` 后缀只对 SO 系有对应形式。** `SOP-8_EP` / `SOP8-EP` / `SOP-8EP` 三种写法都归一到 `ESOP-8`（分隔符可有可无），`TSSOP-16_EP` 归一到 `ETSSOP-16`。别的族名没有公认的 E 形式，硬造一个（`EPSOIC`）比认不出来更糟，所以规则不去认领它们，落回族名规则原样处理：`QFN32-EP` 收成 `QFN-32-EP`（连字符被当成多段编号的一部分，这是既有行为），而 `SOIC-8_EP` 因为编号段不吃下划线，直接报「没有找到封装标签」。
- **`SOP-8` 搜不到 `ESOP-8`。** 它们是两个形状，封装归约层不会把它们判成同一个，这是有意的。唯一的漏网在子串层：`SOP-8` 恰好是 `SOP-8_EP` 的字面前缀，所以写成 `SOP-8_EP` 的记录会拿到一个 0.5 档的弱命中；记成 `ESOP8` 的则完全搜不到。弱命中排在真命中之后，不会顶到前面去。
- **单位只在尺寸码这一个分支里剥。** `5x11mm` 归一到 `5x11`，而 `5mm` 是直插 LED 的直径，走白名单，不会被剥成裸 `5`。所以带单位的写法只有尺寸码这一种：`22mm` 之类的单个数加单位不认。
- **存量不参与检索。** `search qty23` 搜不到东西——存量是独立字段，不在标签里，字符串层够不着它。存货量标签只影响录入这一侧。要按存量筛选是另一个功能（现有的是 `list --low`）。英文等级词同理：`search none` 不会列出没货的元件，它只会拿 `none` 去撞标签，什么也撞不到。
- **直插陶瓷电容不会被自动认作 MLCC。** 「直插」这个封装下可能是陶瓷圆片、电解圆柱、薄膜方块，推不出构造，要自己在标签里写 `MLCC` 或 `陶瓷`。片式的能自动认——片式尺寸码 + 电容在实践中基本就是陶瓷。
- **EIA 三位码和斜杠写法在数值层不被识别。** `104`（= 100nF）和 `100nF/50V` 都解析不出物理量，`search 100nF` 搜不到它们，它们只能作为普通标签参与字符串匹配。
- **没有并发保护。** 单用户手动使用没问题；如果以后写脚本批量调用，两次同时写会互相覆盖（后写的赢）。
- **第一版没有 `edit` 命令。** 标签写错了就 `remove` 掉重录。
- **前缀型的子集不会被报出来。** 包含判定的门槛不含子串层（理由见「重复录入：包含关系怎么判」），所以 `共阴` 与 `共阴绿红` 这类「一条标签是另一条的前缀」的关系看不见。这是拿一点冷门召回换掉一整类误报——子串双向对称，会把「更宽泛」报成「等价」。
- **`--force` 绕过的是确认，不是校验。** 它只回答「我知道重复，照加」（以及「类型推断是猜的我也认」），加进去之后两条记录就是并列的两条，工具不会替你合并，标签写错了也仍然只能 `remove` 掉重录。
- **脚距既是连接器证据，也是直插电容的脚距。** `2p 2.54` 判成 2 脚连接器，可靠；但 `2.54` 也可能是瓷片、薄膜电容的引脚间距，所以 `22p 2.54` 想表达 22pF 时会被读成 22 脚。写 `22pF`（带单位，强度更高）或显式 `C 22p 2.54` 都能绕开。这是「连接器语境下 `Np` 是脚数」这条规则的已知代价，见「必需的两类标签」。
- **包含检查只管录入这一侧。** 库里已经存在的重复（比如同一对录了两遍）不会被它回头找出来，要靠 `list` 自己看。
- **`remove` 与 `stock` 的目标只认 `#编号`。** 写操作要定位到确定的一条，所以宁可要求你先把编号查准。于是 `search #7` / `search 9f1c4e2a` 成立，而 `remove #7` 成立、`remove 9f1c4e2a` 不成立——找要召回，改要精确。
- **`id` 与创建、更新时间没有任何命令会显示。** 它们只存在于数据文件里，`--json` 结果中有 `id`，两个时间戳则哪个输出都没有。要按 id 找元件，`search <id前缀>` 仍然可用。
- **相对增减只对精确存量有效。** 当前是粗略档（1-4 档：极少 / 少 / 多 / 极多）就报错，得先写成精确数。0 不算粗略档——它是精确 0、显示成「无」，所以 `add` 之后可以直接 `stock #7 +1`。
- **值位置的裸数字是精确个数，`add` 的标签里却不是。** `stock #7 23` 设的是精确 23 个，而 `add C 0805 23` 里的 `23` 只是个普通标签——标签按空格分词，认裸数字会把 `0805` 吃成 805 个。代价是 `stock #7 0805` 真的会设成 805 个。
- **`多5` / `少5` / `low5` 会被拒。** `多` / `少` / `low` 已经是档位词，同一个词在同一个位置有两种解释是最坏的一种歧义，所以加了数字也不认，直接报「看不懂」。同理没收 `到` / `满` / `空` 和 `up` / `down` / `in` / `out`。

## 分层与扩展

核心逻辑（归一化、匹配、存储）与命令行层是分开的，全部是模块级纯函数和数据类。`WarehouseKeeper.py` 就是这个分层的第一个消费者——它只做交互循环、行解析与追问，业务逻辑一行都没有复制（`add` / `stock` / `remove` 都是构造一个假 args 转交给 `inventory.py` 的 `cmd_*`）。`-n` 那条规则（切页、报总数、说明切了什么）同样是共用的一份 `apply_limit`：命令行的 `search` / `list` 与交互模式的 `do_search` / `do_list` 四条路径都调它，所以两个入口不会在「切掉了要不要说、怎么说」上各走各的。再加一层界面（Web UI、TUI）可以照同样的路子来：

```python
from inventory import load_inventory, save_inventory, search_components

inv = load_inventory("inventory.json")
hits = search_components(inv.components, ["51R"])
for h in hits:
    print(h.component.tags, h.score)
```

`import inventory` 不会触发 argparse，因为入口有 `if __name__ == "__main__"` 保护。
